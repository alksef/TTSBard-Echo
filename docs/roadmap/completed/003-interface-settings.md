# 003 — Interface settings

- **Статус:** completed
- **Зависимость:** 001
- **Блокирует:** 004, 006, 007

## Результат

Настройки имеют ясную структуру `Общие` и `Интерфейс`. Тема и визуальные параметры
floating находятся в `Интерфейсе`; отдельная страница управления floating и мёртвый
Appearance-компонент устранены. Настройки сообщений находятся в `Общих`, а обычные
успешные изменения интерфейса не создают всплывающий шум.

## Проблема

`SettingsAppearance.vue` присутствует, но недоступен из типизированного списка вкладок.
Те же команды используются в `FloatingPanel.vue`, а тема находится в General. UI
называет backend opacity «прозрачностью» и «opacity» без единого преобразования.

## Целевая структура

```text
Настройки
├── Общие
│   ├── логирование
│   ├── проверка обновлений
│   ├── исключение из захвата
│   └── очищать сообщения через
└── Интерфейс
    ├── тема
    └── плавающее окно
        ├── использовать свою тему
        ├── цвет фона (только при включённой опции)
        ├── прозрачность
        └── click-through
```

Пользовательскую прозрачность главного окна не добавлять в этой задаче без отдельного
решения. Frameless transparency, необходимая shell, является технической деталью, а не
обязательной настройкой.

## Объём работ

### 1. Settings navigation

- Добавить типизированную вкладку `interface`.
- Перенести theme selector из General в Interface.
- Перенести `Очищать сообщения через` из Interface в General без изменения persisted
  поля `message_clear_interval_seconds` и его валидации.
- Переименовать `SettingsAppearance.vue` в `SettingsInterface.vue` либо создать новый
  компонент и удалить старый после миграции.
- Сохранить General только для общесистемных параметров.
- Все пользовательские строки привести к русскому языку.

### 2. Floating appearance controls

- Переключатель `Использовать свою тему` хранится явно в settings. Когда он
  выключен, floating наследует semantic background текущей dark/light темы; когда
  включён — использует сохранённый пользовательский цвет.
- Цвет: color input + текстовое hex-поле с общей валидацией, доступные только при
  включённом пользовательском цвете. Выключение опции не удаляет последнее значение.
- Для существующих settings добавить default/migration, сохраняющие текущий
  эффективный фон и не включающие произвольный цвет у пользователей, которые его не
  выбирали.
- Прозрачность: пользователь видит `0–90% прозрачности`; backend продолжает хранить
  opacity `100–10`. Преобразование реализуется едиными pure functions и тестируется.
  Контрол прозрачности доступен всегда, независимо от собственного цвета.
- Click-through: toggle с optimistic update и rollback при ошибке.
- Удалить кнопку `Восстановить положение`; возврат окна с недоступного монитора
  выполняется автоматически lifecycle-механизмом roadmap 004.

### 3. Live application

- Изменения применяются к открытому floating без перезапуска.
- Настройки после mutation возвращаются в общий `useAppSettings` snapshot/event path.
- Не поддерживать независимые локальные копии дольше выполнения mutation.
- Floating получает актуальную тему при первом mount и при последующем переключении.
- Для startup применить паттерн `app-tts-v2`: ранний валидированный cache исключает
  вспышку default theme, а загруженная persisted backend theme затем становится
  авторитетной и обновляет cache.

### 4. Feedback policy

- Успешная смена темы, собственного цвета, прозрачности и click-through не показывает
  toast/`StatusMessage`: само визуальное изменение является подтверждением.
- Ошибки сохранения остаются видимыми inline, а optimistic state откатывается к
  фактическому backend snapshot.
- Валидационная ошибка hex/числового значения показывается рядом с соответствующим
  полем, а не глобальным всплывающим сообщением.

### 5. Click-through safety

Рядом с toggle разместить явное пояснение:

> Окно перестанет принимать мышь. Выключить режим можно здесь, в главном окне.

- Управление click-through не переносится в floating.
- После ошибки UI возвращается к фактическому backend state.
- Hide/show не должен самопроизвольно менять persisted click-through.

### 6. Cleanup

- Удалить visual settings из старого `FloatingPanel.vue`.
- После roadmap 001 отдельный Floating navigation panel должен исчезнуть полностью.
- Удалить несуществующие CSS variables из старого Appearance CSS и использовать
  актуальные semantic tokens.

## Не входит

- Новый theme editor и произвольные accent colors.
- Прозрачность главного окна как пользовательская функция.
- Управление размером floating.
- Настройки конкретных карточек подключений.
- Полноценная i18n-инфраструктура.

## Приёмка

- В Settings доступны только согласованные вкладки `Общие` и `Интерфейс`.
- Theme selector находится в Interface и меняет оба окна.
- Сохранённая тема применяется при старте, а последующая смена сразу обновляет main и
  floating без всплывающего сообщения об успехе.
- Floating наследует theme background, пока выключен `Использовать свою тему`;
  цветовой контрол активен только при включённой опции.
- Собственный цвет и прозрачность floating применяются сразу и сохраняются после
  перезапуска; прозрачность доступна в обоих режимах цвета.
- `Очищать сообщения через` находится только в `Общих`.
- Пользовательская шкала однозначно подписана как прозрачность.
- Click-through можно безопасно включить и всегда выключить из главного окна.
- В Interface нет кнопки ручного восстановления положения.
- Нет второго владельца визуальных настроек.

## Верификация

- Component tests optimistic update/rollback и disabled state.

- `npm run build` и применимые Rust checks.
- Ручная проверка persist/restart для theme, custom-color toggle/value, opacity и

- Ручная проверка отсутствия success toast при изменениях Interface и наличия inline
  ошибки при неуспешной mutation.
