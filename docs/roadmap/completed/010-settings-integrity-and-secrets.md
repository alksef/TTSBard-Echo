# 010 — Целостность и безопасность настроек

- **Статус:** completed
- **Приоритет:** P0
- **Зависимости:** 008
- **Блокирует:** 013
- **Завершён:** 2026-09-15

## Результат

Сбой записи не повреждает настройки, access tokens не хранятся открытым текстом,
а WebView работает с явной Content Security Policy.

## Проблема

`settings.json` перезаписывается напрямую и содержит access token. При сбое
между открытием и завершением записи файл может стать неполным. В Tauri config
сейчас установлено `"csp": null`.

## Решение, требующее выбора

Предпочтительный Windows-вариант — хранить token через Credential Manager или
DPAPI, а в JSON оставлять только ссылку/идентификатор. Более простой вариант —
DPAPI-шифрование значения прямо в JSON. Формат необходимо закрепить ADR до
реализации миграции.

## Объём работ

1. Ввести атомарную запись settings/windows: temporary file, flush, replace и
   восстановление последнего корректного состояния.
2. Добавить версию схемы и миграцию существующего plaintext token.
3. Исключить token из runtime snapshots, ошибок, debug formatting и frontend
   events, где он не нужен.
4. Ограничить права файла конфигурации средствами Windows, где это применимо.
5. Включить CSP, достаточную для локальных assets и необходимых Tauri IPC.
6. Добавить диагностическое сообщение для повреждённого конфига без вывода
   секретного содержимого.

## Не входит

- Облачная синхронизация секретов.
- Общий password manager для других приложений TTSBard.
- Изменение серверной схемы аутентификации.

## Приёмка

- Прерванная/ошибочная запись сохраняет последний валидный config.
- После миграции plaintext token отсутствует в `settings.json`.
- Обновление, удаление и повторное добавление token работают предсказуемо.
- CSP не блокирует основное и floating окна и не разрешает лишние источники.
- Логи, IPC snapshots и пользовательские ошибки не раскрывают token.

## Верификация

- Rust unit tests атомарной записи, миграции и recovery;
- negative tests на token leakage;
- frontend contract tests после изменения DTO;
- `npm test`, `npm run build`, Rust fmt/Clippy/tests;
- ручная миграция копии реального v0.1.0 config и проверка двух окон.

## Завершение (2026-09-15)

Схема хранения секретов закреплена в [ADR-0024](../../decisions/0024-roadmap-010-secret-storage.md):
DPAPI-шифрование значения прямо в `settings.json` (base64 на прежней позиции),
Windows Credential Manager отклонён (два хранилища → рассинхрон и висячие
ссылки), DTO настроек остаётся единственным легитимным каналом токена в вебвью,
на не-Windows шифрования нет (Windows-first), `schema_version` — деталь
дискового формата и в DTO не попадает.

Сделано по пунктам объёма:

1. **Атомарная запись** — `src-tauri/src/config/atomic.rs`: tmp-файл → flush +
   sync → `.bak` с предыдущей версией → rename; единая точка записи для
   `settings.json` и `windows.json` (включая первый запуск). Прямых
   `std::fs::write` конфигов не осталось.
2. **Восстановление** — `src-tauri/src/config/recovery.rs`: повреждённый файл не
   роняет старт; карантин `<имя>.corrupt-<timestamp>`, восстановление из
   `.bak`, иначе defaults; восстановленное состояние персистится; warn-
   диагностика без содержимого файла. Восстановление очищает битый target
   перед записью, чтобы не затирать валидный `.bak`.
3. **Схема и миграция** — дисковый конверт `StoredSettings` с `schema_version`
   (v1 = формат v0.1.0, v2 = текущая); `src-tauri/src/config/secret.rs`:
   DPAPI (CryptProtectData/CryptUnprotectData, `cfg(windows)`), одноразовая
   идемпотентная миграция при загрузке через атомарную запись; токен, который
   не расшифровывается (другой профиль/машина), читается как «недоступен»
   без паники и без дампа, восстанавливается повторным вводом через форму.
4. **Redaction** — мёртвый `MaskedAccessTokens` заменён на `SecretAccessToken`
   (Debug печатает `[masked]`, serde-форма прежняя); сентинел-тесты закрывают
   runtime snapshot, события, тексты ошибок, логи и Debug-вывод; URL в
   ошибках свободен от токена (токен легитимно уходит только в Cookie).
5. **ACL** — `src-tauri/src/config/acl.rs`: защищённый DACL (текущий
   пользователь + SYSTEM + Administrators, наследуемые широкие ACE
   отбрасываются) на конфиг-файлы, включая `.bak`/`.tmp`/`.corrupt-*`;
   применяется при записи (ошибка = отказ записи) и при загрузке
   существующих файлов (best-effort); no-op на не-Windows.
6. **CSP** — прод: `default-src 'self'; connect-src ipc: http://ipc.localhost;
   img-src 'self' data:; style-src 'self' 'unsafe-inline'` (style — осознанное
   исключение для динамических стилей Vue); dev — то же + HMR-websocket.
   Инлайн theme-скрипты покрываются автохэшами Tauri; скриптовых ослаблений и
   внешних источников нет.

Дефект вне объёма, найденный задачей CSP: в `src/styles/index.css` оставался
удалённый `@import` Google Fonts — строгая CSP блокирует внешние источники,
поэтому импорт убран (типографика на системных фоллбеках Segoe UI /
Cascadia Code); самохостинг Manrope и JetBrains Mono — отдельный follow-up.

Исполнение: задачи 001–003 выполнены локальным агентом qwen (ADR, атомарная
запись, recovery; независимое ревью — в `.work/ai/2026-09-14-roadmap-010-settings-integrity/reviews/`),
замечания ревью исправлены; задачи 004–008 — сабагенты ZCode с промежуточными
коммитами; задачи 009–010 — операторская сессия.

Верификация (фактические результаты):

- `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`
  — чисто; `cargo test` — 79 passed / 0 failed;
- `npm test` — контракты `check:ipc ok` (30 команд), `check:settings ok`,
  Vitest 72 passed (6 файлов); `npm run build` — зелёный;
- ручная E2E на реальном конфиге: миграция v1 → v2 при первом запуске
  (в логе «Migrated settings file … from schema version 1 to 2»), plaintext
  токена в файле нет (DPAPI-блоб, JWT-подобных строк нет), подключение
  поднимается в «Подключено» с расшифрованным токеном, в логе токен
  печатается как `(masked)`;
- жизненный цикл токена через UI: добавление подключения с токеном →
  в файле зашифрованный блоб (сентинел-строка в файле отсутствует),
  редактирование с очисткой токена → `access_token: null`, удаление
  подключения → конфиг в исходном составе;
- corrupt-тест: обрезанный пополам `settings.json` → старт не валится,
  warn-диагностика, карантин `settings.json.corrupt-1789459797945`,
  состояние восстановлено из `.bak` (откат последнего изменения списка —
  ожидаемая гранулярность одной предыдущей версии);
- `icacls`: `settings.json` и `windows.json` — только
  `Al:(F)`, `СИСТЕМА:(F)`, `Администраторы:(F)`, наследуемых широких групп нет;
- smoke двух окон на debug-сборке: главное — карточка подключений с живым
  статусом, floating переключается с тайтлбара в обе стороны с синхронизацией
  подписи, контент рендерится, «Выйти из Echo» завершает процесс.

Известные ограничения: на не-Windows токен остаётся в JSON открытым текстом
(по ADR; Linux CI зелёный — крипто-код за `cfg(windows)`, зависимость под
target-gate); `.bak` хранит ровно одну предыдущую версию, поэтому
восстановление откатывает последнее изменение конфига; доставка `devCsp` в
desktop-dev зависит от механизма Tauri (прод-CSP доставляется гарантированно);
самохостинг шрифтов не выполнен (follow-up).
