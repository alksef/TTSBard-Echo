- **Статус:** completed
- **Зависимости:** нет; первая реализационная задача программы
- **Reference:** `D:\RustProjects\app-tts-v2` на baseline `473d33c`
- **Следующие задачи:** 002, 003, 004, 005

## Результат

Echo использует актуальную базовую дизайн-систему TTSBard и собственный компактный
frameless shell. Главное окно имеет надёжный кастомный titlebar, а показ floating
становится оперативным действием в titlebar, а не отдельным разделом Sidebar. Тема и
позиция главного окна корректно восстанавливаются при старте, а минимальный размер не
позволяет сломать компоновку.

## Обоснование

Сейчас CSS Echo формально похож на TTSBard, но уже разошёлся с reference: структура
раздроблена, light theme не завершена, часть токенов ошибочна, а floating использует
ручной набор цветов из HTML. Главное окно всё ещё использует системную рамку, хотя
старый migration plan предусматривал custom titlebar.

## Зафиксированные UX-решения

- Высота titlebar ориентировочно 36 px, как в TTSBard.
- Слева — `Echo`; справа — toggle floating, minimize, close.
- Maximize не добавляется без отдельной продуктовой необходимости.
- Кнопки не входят в drag-region.
- Отдельный пункт `Плавающее окно` удаляется из Sidebar.
- Кнопка Exit в Sidebar удаляется; жизненный цикл приложения выражается titlebar и
  tray menu.
- Закрытие главного окна рекомендуется трактовать как hide-to-tray, если это не
  противоречит уже реализованной tray-семантике. Явный Exit остаётся в tray.

## Объём работ

### 1. Базовые стили

Свести базовый слой к понятной структуре:

```text
src/styles/
├── variables.css
├── gradients.css
├── base.css
├── components.css
├── echo.css
└── index.css
```

- Перенести актуальные семантические токены из reference.
- Сохранить Echo-специфичные значения отдельным слоем, а не менять скопированные
  токены по компонентам.
- Реализовать полный dark/light набор.
- Исправить ошибочные и отсутствующие variables.
- Оставить один global entrypoint `src/style.css`.
- Удалить дублирующие theme/variable imports после миграции потребителей.
- Не переносить стили компонентов TTSBard, которых нет в Echo.

### 2. Application shell

- Добавить `AppTitlebar.vue`.
- Перестроить `App.vue` в вертикальную композицию `titlebar + content wrapper`.
- Обновить grid/background так, чтобы он учитывал titlebar и collapsed Sidebar.
- Перевести `tauri.conf.json` главного окна на явный label `main`,
  `decorations:false`, `transparent:true`.
- Проверить capabilities для minimize, close/hide, show, start-dragging и получения
  visibility.
- Не применять `data-tauri-drag-region` к интерактивным кнопкам.
- Задать минимум главного окна `550 × 350` outer px как нижнюю границу текущего
  рабочего layout; если titlebar/content требуют большего размера, увеличить минимум
  по результату проверки, но не допускать скрытия controls или горизонтального
  переполнения.

### 3. Startup theme

Адаптировать двухступенчатый паттерн `app-tts-v2`, а не ждать mount компонента на
дефолтной теме:

- до загрузки Vue применить валидированную тему из `localStorage` к
  `document.documentElement[data-theme]`, чтобы исключить вспышку неверной темы;
- после загрузки settings применить persisted backend theme как авторитетную и
  синхронизировать её обратно в `localStorage`;
- при отсутствии/повреждении cache использовать `dark`, но не затирать корректную
  persisted theme до завершения загрузки settings;
- применить соответствующий `tauri::Theme` ко всем существующим окнам при setup и при
  последующем переключении.

### 4. Floating toggle contract

Кнопка titlebar не должна угадывать состояние локально. Нужен минимальный контракт:

- получить фактическую видимость floating при загрузке;
- переключить видимость одной командой либо согласованной парой show/hide;
- получить событие с новым `visible: boolean` после изменения;
- блокировать повторный click, пока команда выполняется;
- восстанавливаться после ошибки через повторный snapshot.

Конкретные имена могут быть уточнены при реализации, но payload должен быть типизирован
и проверяем. Событие без payload не считается достаточным.

### 5. Main window position persistence

- Сохранять позицию главного окна после завершения перемещения с debounce, а также при
  hide и штатном shutdown.
- Восстанавливать позицию до показа окна и проверять её против monitor work areas с
  учётом DPI.
- Если монитор отключён или окно полностью недоступно, автоматически вернуть его на
  доступный экран; отдельная пользовательская кнопка для этого не нужна.
- Не путать программное центрирование/restore с пользовательским перемещением и не
  перезаписывать корректную позицию дефолтной при старте.

### 6. Sidebar

- Оставить разделы `Подключения` и `Настройки`.
- Удалить навигацию к старому `FloatingPanel`.
- Удалить Exit из Sidebar.

## Приёмка

- Главное окно не имеет системной рамки и перетаскивается только за titlebar.
- Главное окно нельзя уменьшить ниже рабочего минимума, его позиция сохраняется после
  перемещения и восстанавливается на доступном мониторе после перезапуска.
- Minimize работает; close следует подтверждённой tray-семантике.
- Кнопка floating показывает фактическое состояние после старта и после внешнего
  переключения hotkey/tray.
- Sidebar больше не содержит Floating и Exit.
- В light/dark режимах нет нечитаемых поверхностей и отсутствующих CSS variables.
- Сохранённая light/dark тема применяется при старте без промежуточного сброса на
  default и затем остаётся синхронизированной с backend settings.
- Existing settings/error state не перекрывает titlebar и остаётся доступным.
- Общие стили не зависят от абсолютного пути к `app-tts-v2`.
