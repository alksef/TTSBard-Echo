# 012 — Представление и история событий

- **Статус:** proposed, продуктовый scope требует утверждения
- **Приоритет:** P2
- **Зависимости:** 009, 011

## Результат

Echo становится полезным при нескольких активных источниках: пользователь
управляет отображением событий, может быстро вернуться к недавнему сообщению и
выбрать подходящий layout floating окна.

## Варианты поставки

- **Минимальный:** client-side фильтры и 20–50 последних сообщений только в
  памяти до закрытия приложения.
- **Рекомендуемый:** ограниченная локальная история с TTL, лимитом размера и
  явной кнопкой очистки.
- **Расширенный:** профили layout/фильтров для разных сценариев стрима.

## Объём рекомендуемого варианта

1. Определить единый именованный event DTO вместо новых tuple payload.
2. Добавить фильтры по connection, event type и тексту.
3. Хранить ограниченную историю с TTL и жёстким лимитом размера.
4. Добавить очистку всей истории и отдельных connection records.
5. Реализовать compact, detailed и single-message floating layouts.
6. Сохранить доступность: keyboard navigation, reduced motion, readable contrast
   и отсутствие горизонтального overflow.
7. Не сохранять typing previews и секретные поля.

## Не входит

- Неограниченный архив и полнотекстовая база данных.
- Облачная синхронизация.
- Аналитика поведения пользователя.

## Приёмка

- 10 одновременных соединений не делают main/floating UI неуправляемым.
- Лимиты истории соблюдаются после restart и миграции.
- Очистка физически удаляет данные, а не только скрывает их в UI.
- Фильтры и layout восстанавливаются предсказуемо.
- Длинный URL, multiline, Unicode и rapid event burst не ломают layout.

## Верификация

- pure tests фильтрации, лимитов, TTL и миграции;
- component tests layouts и empty states;
- stress fixture с burst событий;
- ручная матрица 0/1/4/10 connections, обе темы и 100/125/150% DPI.
